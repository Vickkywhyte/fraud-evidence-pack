# ADR-001: Tiered Intelligence — Regex/Rules + Future Local LLM

## Status

Accepted

## Date

2026-10-26

## Context

Fraud Evidence Pack needs to analyse unstructured text (chat logs, emails, letters) and identify fraud typologies, extract warning indicators, and build event timelines.

Three approaches were considered:

| Approach | Accuracy | Privacy | Cost | Offline |
|---|---|---|---|---|
| **Cloud LLM API** (e.g., GPT, Claude) | High | None — evidence sent to third party | Per-token billing | No |
| **Local LLM via WebGPU** | Medium–High | Full — runs in browser | Zero | Yes |
| **Regex/rule-based matching** | Low–Medium | Full — runs in browser | Zero | Yes |

The target users are fraud victims. Their evidence contains bank details, personal communications, and financial records. Sending this data to any external API — even an encrypted one — is unacceptable. Many victims are already in a state of distrust after being scammed; a tool that phones home would not be adopted.

## Decision

We adopt a **Tiered Intelligence** architecture:

### Tier 1: Regex and Rule-Based Analysis (implemented now)

- **Typology matching:** Keyword lists mapped to five fraud categories (Impersonation, Advance Fee, Romance Scam, Investment Scam, Account Takeover). A typology matches if any of its keywords appear in the text (case-insensitive).
- **Warning flag extraction:** A curated list of 38 phrases associated with social engineering, urgency tactics, and fraudulent payment methods.
- **Timeline extraction:** Regex-based date detection across common formats (DD/MM/YYYY, YYYY-MM-DD, "January 5, 2024", "5 March 2024") with surrounding context.

Tier 1 is deterministic, fast, and requires zero dependencies beyond the browser's built-in regex engine. It is the permanent fallback.

### Tier 2: Local WebGPU LLM (future)

- A small language model (e.g., Phi-3, Gemma 2B) running entirely in the browser via WebGPU/WASM.
- Would provide: narrative summarisation, entity relationship extraction, confidence scoring, and nuanced typology detection that keyword matching misses.
- Strictly opt-in: the user must explicitly enable it, and the model is downloaded to their device.
- Graceful degradation: if WebGPU is unavailable or the user declines, Tier 1 results are used without any loss of core functionality.

## Trade-offs

### What we gain

- **100% privacy guarantee.** Zero network requests. Auditable by anyone inspecting the browser's Network tab.
- **Zero cost.** No API keys, no billing, no rate limits.
- **Offline capability.** Works on planes, in areas with poor connectivity, or on air-gapped machines.
- **Deterministic results.** Tier 1 produces identical output for identical input. No temperature, no randomness, no model drift.
- **Instant processing.** No latency from API round-trips. Regex on modern hardware processes megabytes of text in milliseconds.

### What we lose

- **Nuanced understanding.** Tier 1 cannot detect novel fraud patterns, understand implied meaning, or disambiguate context. "I love this investment" matches "Investment Scam" even in a legitimate context.
- **Narrative summarisation.** Tier 1 cannot produce a human-readable summary of what happened. It extracts signals but does not synthesise.
- **Entity resolution.** Tier 1 cannot determine that "John," "Mr. Smith," and "the caller" refer to the same person.
- **Confidence scoring.** Every Tier 1 match is binary (present/absent). There is no probabilistic weighting.

### Why this is acceptable

The tool's primary job is to **structure evidence**, not to **judge it**. A list of matched typologies and warning flags with a chronological timeline gives a bank's fraud team or an ombudsman vastly more to work with than a folder of unsorted screenshots.

Tier 1 accuracy is sufficient for this purpose. False positives (a matched keyword that isn't actually fraud) are visible in the redacted transcript and can be assessed by the human reader. False negatives (missed fraud indicators) are mitigated by including the full redacted text in the PDF — nothing is hidden.

Tier 2 is designed to enhance, not replace. When it ships, it will add confidence scores and summaries alongside the Tier 1 signals, not substitute for them.

## Consequences

- All analysis code must run synchronously or via browser-native async APIs. No `fetch()`, no `XMLHttpRequest`, no WebSocket.
- The test suite must validate Tier 1 accuracy against known fraud text samples.
- The UI must clearly label results as "rule-based analysis" to set appropriate expectations.
- When Tier 2 is introduced, the `Tier1Result` interface must remain stable — Tier 2 extends it, never replaces it.
